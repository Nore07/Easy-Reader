# Security Policy / 安全策略

## Supported versions / 支持版本

Security fixes are prioritized for the latest published release and the current default branch. Older releases may not receive fixes; please update to the latest release where possible.

安全修复优先面向最新发布版本和当前默认分支。旧版本可能不会收到修复；条件允许时，请先升级到最新版本。

## Reporting a vulnerability / 报告安全漏洞

Please do **not** report vulnerabilities through public Issues, Discussions, or Pull Requests.

请**不要**通过公开的 Issue、Discussion 或 Pull Request 报告安全漏洞。

Use GitHub's private vulnerability reporting option in the repository's **Security** tab when it is available. If you cannot access that option, contact the repository owner privately through a contact method on the [Nore07 GitHub profile](https://github.com/Nore07). Do not publish exploit details while arranging a private reporting channel.

如果仓库 **Security** 页面提供 GitHub 私密漏洞报告入口，请使用该入口。若无法使用，请通过 [Nore07 的 GitHub 个人资料](https://github.com/Nore07)中的联系方式私下联系仓库所有者。在建立私密报告渠道前，请勿公开漏洞利用细节。

Include the affected QuietReader version, Windows version, impact, and steps needed to reproduce the issue. Share only the minimum proof needed. Remove book titles, personal file paths, account details, and other private data from logs or screenshots.

请说明受影响的 QuietReader 版本、Windows 版本、影响范围和复现步骤，并仅提供必要的验证信息。日志或截图中请移除书名、个人文件路径、账户信息及其他私人数据。

## Response / 处理方式

Maintainers will review reports, investigate the issue, and coordinate a fix and disclosure with the reporter. Response time depends on the report and maintainer availability; please avoid sharing details publicly until a disclosure plan is agreed.

维护者会审阅报告、调查问题，并与报告者协调修复和披露安排。响应时间取决于问题情况和维护者的可用时间；双方商定披露计划前，请勿公开相关细节。
